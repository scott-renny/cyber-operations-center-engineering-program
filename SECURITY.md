# Security Policy

## Reporting a Vulnerability

Do not report vulnerabilities, credentials, exploit details, private infrastructure identifiers, or personal data in a public issue, discussion, or pull request.

Use the repository's **Security** tab and select **Report a vulnerability** to open a private vulnerability report:

<https://github.com/scott-renny/cyber-operations-center-engineering-program/security/advisories/new>

If private reporting is unavailable, contact the maintainer through a private channel listed on the maintainer's GitHub profile. Send only enough information to establish a private reporting channel; do not disclose sensitive technical detail publicly.

## Include

- A concise description of the issue
- Affected component and version, when known
- Reproduction conditions using sanitized or synthetic data
- Potential impact
- Suggested mitigation, if available

Do not include live credentials, household data, raw logs, forensic images, or identifying infrastructure details.

## Response

Reports will be acknowledged when received, assessed for scope and impact, and handled according to the program's incident, evidence, secrets-management, and sanitization controls. Public disclosure occurs only after remediation and publication review.

## Supported Versions

This program is under active development. Security fixes apply to the current `main` branch unless a release states otherwise.
